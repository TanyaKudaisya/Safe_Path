How a report travels

From the road to a closed ticket, with a record at every step.

  1. Photograph

    Take a photo, or scan with the live camera. The location comes from your phone.

  2. Detect

    A YOLO model finds the potholes and gives each one a confidence score.

  3. Report

    The photo, position and scores are saved as a report in the database.

  4. Review

    Staff mark it in progress, resolved, or rejected with a reason.

  5. Follow up

    The citizen sees the new status in the app.

What is inside

Two audiences, one backend.

For citizens

  • Photo detection with a score for every pothole found
  • Live camera scan that draws boxes and can file reports on its own
  • Map of open reports nearby and your own report history
  • Sign-up with phone number, profile editing, password reset by emailed code

For road staff

  • Reports on a map and in a list, filtered by status
  • Workflow from pending to in progress to resolved or rejected
  • Zone statistics and hotspots, with CSV export
  • Admin role plus a company email domain required, checked on every request
  • React Native (Expo)
  • Spring Boot, Java 21
  • MongoDB Atlas
  • FastAPI and YOLO
  • JWT and rate limiting
  • Cloudinary
  • Render

Good to know

  • Everything runs on free hosting, so the first request after a quiet period can take about a minute.
  • Live camera scanning is slow on this hosting. It runs much faster when the detection service runs on a laptop.
  • This app build does not receive push notifications yet. Status changes show up when you open the app.
  • Android only.
